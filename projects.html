WatchTower

What happens after your software goes live?

WatchTower brings errors, performance metrics, and user events into a single dashboard. The goal is to give browser activity a place where a developer can follow it.

Inside the build

I led the frontend work, connecting browser SDK telemetry with a Supabase/PostgreSQL backend and Clerk authentication. Jest, Playwright, and GitHub Actions support testing and delivery.

Reg2Schedg

A screenshot is a starting point, not a schedule.

Course planning means piecing together schedules, evaluations, and professor information. Reg2Schedg turns a schedule screenshot into structured data and brings that context into the planning process.

Inside the build

I built a research pipeline with Browser Use and normalized course evaluations in Supabase. The platform combines course logistics, professor ratings, and student sentiment to help students compare options.

  • TypeScript
  • Python
  • SQL
  • Supabase

Receipt → items → shared expenses

Mobile application · OCR & AI

Splitr

The meal is over. The receipt math shouldn’t take all night.

Splitr turns receipt photos into structured items for shared expenses. It brings receipt parsing and user history into a cross-platform mobile app.

Inside the build

I developed the React Native app with Expo, using Google Vision OCR and an OpenAI model to structure receipt data. Firebase handles authentication, SMS verification, and saved receipt history.

  • React Native
  • Expo
  • FastAPI
  • Firebase
  • TypeScript
